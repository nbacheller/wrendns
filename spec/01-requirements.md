# 01 — Requirements (the contract)

Every requirement has a stable ID. Code, tests, and PRs **must** reference IDs (e.g., `// REQ: FLT-004`, test name `flt_004_wildcard_suffix_block`). Priority: **P0** = v1.0 must ship; **P1** = v1.x; **P2** = later / stretch.

Detailed behavior lives in the referenced spec section. If this table and a section disagree, the section wins, and fix the table.

## DNS core (DNS) — see `03`
| ID | Pri | Requirement |
|---|---|---|
| DNS-001 | P0 | Serve DNS over UDP and TCP (RFC 1035, RFC 7766) on configurable addresses/ports, IPv4 and IPv6. |
| DNS-002 | P0 | Serve DoT (RFC 7858) with configurable cert/key, plus ACME (via cert files that cert-manager mounts in k8s). |
| DNS-003 | P0 | Serve DoH (RFC 8484) over HTTP/2 with GET and POST on `/dns-query` and `/dns-query/{client-id}`. |
| DNS-004 | P1 | Serve DoH over HTTP/3 and DoQ (RFC 9250). |
| DNS-005 | P0 | EDNS(0) (RFC 6891), with a configurable advertised UDP payload size (default 1232) and TC-bit truncation. |
| DNS-006 | P0 | Sharded in-memory cache that stores wire-format responses and rewrites ID and TTLs on hit; honors min/max TTL clamps; negative caching (RFC 2308). |
| DNS-007 | P0 | Serve-stale (RFC 8767), with configurable max stale age and client-response timeout. |
| DNS-008 | P1 | Prefetch: hot entries refresh asynchronously when remaining TTL < 10% (configurable). |
| DNS-009 | P1 | Cache persistence: an optional dump on shutdown and load on startup. |
| DNS-010 | P0 | Local records: A, AAAA, CNAME, PTR (auto-generated from A/AAAA), TXT, SRV, MX; wildcard local records; hosts-file import. |
| DNS-011 | P0 | DNSSEC validation (RFC 4033–4035) for forwarded and recursive answers. Bogus → SERVFAIL with EDE 6. Configurable negative trust anchors. |
| DNS-012 | P1 | Full recursive resolution from root hints, with QNAME minimization (RFC 9156) and aggressive NSEC caching (RFC 8198). |
| DNS-013 | P0 | Extended DNS Errors (RFC 8914) on blocked, stale, and failed answers. |
| DNS-014 | P0 | Per-client rate limiting (token bucket; default 1000 q/60 s like Pi-hole), with REFUSED or drop as the action and an allowlist exemption. |
| DNS-015 | P1 | ECS (RFC 7871): strip, pass through, or substitute per upstream; never leak ECS by default. |
| DNS-016 | P1 | DNS64 (RFC 6147) per group. |
| DNS-017 | P0 | Conditional forwarding / per-domain upstream routing, including reverse zones (Pi-hole `rev-server` parity). |
| DNS-018 | P1 | Local zones: a small authoritative zone loaded from an RFC 1035 zone file or config (split-horizon views per group). |
| DNS-019 | P0 | Refuse ANY queries (RFC 8482 minimal response), refuse zone transfers (AXFR, IXFR) without forwarding, and drop malformed packets cheaply. **Special names** (`spec/03` §3 step 4; ADR-014, ADR-904), answered without forwarding: `localhost`, `*.invalid`, the Firefox canary, CHAOS class, private reverse zones, iCloud Private Relay's `mask.icloud.com`/`mask-h2.icloud.com` (NXDOMAIN, on by default), `resolver.arpa` (never forwarded; DDR, RFC 9462, for this node's reachable encrypted listeners when `[special] ddr_name` is set, else no data), and optionally (`single_label_nxdomain`, off by default; Pi-hole's `domain-needed`) NXDOMAIN for single-label A/AAAA/HTTPS names that no local data, zone, device name or route covers. The Pi-hole importer maps the matching settings. |
| DNS-020 | P1 | PROXY protocol v2 on TCP/DoT/DoH listeners, to preserve client IPs behind load balancers. |
| DNS-021 | P2 | NSID (RFC 5001), off by default: a query that asks for it gets the answering node's name, so a client can tell which node or pod answered behind a shared address (owner request 2026-10-09, from Technitium #1932). |
| DNS-022 | P1 | **Stub zones** (BIND `static-stub`, Unbound `stub-zone`): a domain whose own servers are authoritative only is resolved iteratively starting at those servers instead of the root, following the delegations they give, with a health check they answer (the zone's SOA); set from the config, the API (`stub: true` on a forward), MCP, and the UI (community request 2026-11-14, PR #10). |
| DNS-023 | P1 | **Device names in DNS** (fork owner request 2026-11-16; community request: DNS kept in step with DHCP leases and static leases, without a DHCP server, ADR-091): with `[local] device_domain` (off by default), every device TelltaleDNS knows by name answers an A record `<name>.<domain>` and a PTR for its address: named devices with one address or a MAC, the routers' DHCP clients and reservations and Home Assistant's devices (`[[router]]`), the other nodes' routers (CLU-002), and with `device_mdns` the names devices announce. Names become one DNS label (`Kitchen Tablet` → `kitchen-tablet`); when two devices want one label, one keeps it by a fixed order (ADR-901). Configured records, hosts files, and a zone's own records win; a device name inside a zone answers before the zone's NXDOMAIN. Built off the query path; the query path pays one branch with it off and one lock-free load with it on (`02` §3). `GET /api/v1/dhcp/leases` shows each device's `dnsName`; explain says when a device name answered. A device the routers report with IPv6 addresses also answers AAAA for each usable one and has an `ip6.arpa` PTR, by the same label and offline rules (T24.8, ADR-983). Discovery data never names a device in DNS (ADR-910). That covers SNMP, imports, the neighbour-table inventory source, UniFi `stat/alluser`/`stat/device` and Home Assistant devices without entities. With `device_inventory_addresses` on, discovery may only supply the address of a device that is already named (DSC-012). |

| FLT-008 | P0 | Block response modes: NXDOMAIN, NODATA, null IP (0.0.0.0/::), custom IPs, REFUSED; always with EDE 15 (Blocked) or 17 (Filtered) plus the rule attribution text (configurable). |

| FLT-010 | P1 | Schedules: per-group weekly time windows that enable extra lists or block all ("bedtime"). |

| FLT-012 | P1 | Blocked-services presets (one-click service bundles: TikTok, Facebook, gaming, etc.), shipped as data files. |

| FLT-016 | P2 | Per-group AAAA filtering: a group's AAAA questions get no data (devices fall back to IPv4 on a network with broken IPv6); local data still answers, blocks still win, not combined with DNS64 (owner request 2026-10-09, from Pi-hole's feature requests). |

| FLT-901 | P1 | **Content categories** (owner request 2026-11-18; ADR-994, ADR-995): a catalog (`presets/categories/*.toml`) of categories grouped like UniFi's content filter, each backed by maintained open lists (licence, URL, cadence recorded), downloaded at runtime and shared across groups; a group turns categories on; categories with no open maintained source are listed as not offered. Cost (entries, estimated memory) shown before selecting. |
| FLT-902 | P1 | **Filter profiles** (owner request 2026-11-18; ADR-994): a profile is a group. The Groups page is a profile list (Name, Source, Filter Scope, Safe Search, Schedule) and editor (sources: networks and devices with a private-MAC warning, Ad Block, safe search per engine, Filtering Off, Basic or Enhanced, category picker with search, Select All and Deselect All); devices can be added from the editor. |

## Network inventory (DSC) — see `10` M25, ADR-907 to ADR-913
Fork requirements (fork owner request 2026-11-16). Discovery only reads; it never probes, and its data never feeds DNS policy or names (ADR-907, ADR-910).

| ID | Pri | Requirement |
|---|---|---|
| DSC-001 | P1 | **Network inventory scope** (owner request 2026-11-16). Off by default. `[discovery]` is a shared section that runs on one designated node: `node`, else the primary or the standalone node, never ephemeral pods or witnesses. TelltaleDNS only reads: SNMP GET, GETNEXT and GETBULK to listed infrastructure and to class 1–3 inventory addresses inside configured subnets, plus UniFi and Home Assistant API reads. It never sweeps a range, never sends ICMP, TCP connect probes or ARP/NDP/mDNS solicitations, and never schedules scans (ADR-907). Every SNMP destination must be an RFC 1918 IPv4 literal; anything else, including 100.64.0.0/10 and all IPv6, is refused. Config writes are admin only, no agent scope writes them, and file edits are audited at start and reload. |
| DSC-002 | P0 | **DNS never depends on discovery** (CLU-004). SNMP I/O and the codec run in a separate `telltale discovery-worker` process. Import parsing runs in a separate credential-free `--import` worker. A worker crash, hang, allocation failure or OOM never affects query answering, and the systemd unit sets `OOMPolicy=continue`. | DSC-004 | P1 | **Infrastructure polling:** for each listed agent, ARP (ipNetToPhysical, else ipNetToMedia), IF-MIB, Q-BRIDGE/BRIDGE forwarding per VLAN (FDB ID mapped to VLAN ID, bridge port mapped to ifIndex) and LLDP neighbours.
