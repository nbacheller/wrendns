What's new in 1.1 In development

The release you download above is 1.0.0. The next version, 1.1, is being built on main, and builds of main (the edge channel, installed with install.sh --edge or the :edge image) already carry the items below. Each one is marked Coming in 1.1 where it is described on this site, so a page never promises a feature that 1.0.0 lacks. There is no release date yet. Edge builds change often and are not for a network you rely on.

  • A listener on a public address answers only devices that carry a key. An encrypted listener on a public address now refuses a device that does not carry its key, so it cannot be used as an open resolver. This changes what happens when you upgrade: read this first.
  • Change listeners from the web UI. Add, edit or remove where a node answers. The new listener opens next to the old ones, the node asks it a test question, and the change rolls back unless you confirm. How.
  • Allowed networks in the web UI. One list for the whole cluster, checked before it is applied. How.
  • Locations. Give a site, a lab or a VLAN its own device names (laptop.lab.example.net), with a Locations page and a pin for a single device. How.
  • A stricter, easier to watch built-in resolver. It no longer asks servers on your own machine or network, limits expensive DNSSEC proofs (RFC 9276), remembers how fast and how well each server answers, counts what it asks, and can show the walk of one lookup under Why?. How.
  • Flush the cache by type or kind, and flush the built-in resolver's memory of servers. How.
  • Five opt-in category lists from blocklist.packettale.com: stalkerware, typosquatting, violence and gore, remote-access tools and push notifications. How.
  • Syslog over TCP or TLS keeps events while the collector is down, instead of losing them. How.
  • Set dnstap from the web UI. An admin sets the dnstap output in Settings → System, for each node. Turning it on, or copying more of your devices' queries, goes through a review where you type a phrase, and a saved change takes effect after that node restarts. How.
  • OTLP export can be gzip-compressed, and every signal names its node. A Compression choice on the export card sends metrics and traces gzip-compressed (still JSON over HTTP), and each signal carries service.instance.id. A setup guide covers the Home Assistant OpenTelemetry Collector add-on. How.
  • Safer upgrades of a cluster. A new kind of shared setting is held back until every node can read it. How.
  • A smaller web UI. The help text is fetched from the node when you first open a "?".

Every change that needs you to act on upgrade is listed under Upgrading in the release notes.
