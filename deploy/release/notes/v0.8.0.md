## Upgrading

- **Credentials are no longer shown anywhere they were copied.** An upstream's `headers` and `args`, a password in a URL (an upstream's `url` or `proxy`, an alert destination's `url`), an OIDC `client_secret`, and `[telemetry.otlp] headers` now read `<redacted>` in `GET /api/v1/config/entries`, write responses, the audit log, the TOML to keep a change in Git, pin and version diffs, MCP, and `telltale config check --print` (`--show-secrets` prints them on the node). A tool that edits an entry by sending back what it read keeps working: `<redacted>` keeps the stored value as long as the entry's `url`, `proxy`, `tls_server_name`, `tls_ca`, and `bootstrap` are unchanged. A write that sends `<redacted>` with a new destination is refused (422 `credential_reentry_required`): send the credential itself.
- **Older audit entries may hold credentials.** Entries written before this version recorded a change's full body, so an upstream's headers can be in them. The audit log's hash chain can't be rewritten: treat an older `state.db`, and backups made from it, as sensitive.
- **`Idempotency-Key` records start over.** The upgrade deletes the stored retry records (they held request bodies); a retry of a request made before the upgrade is applied again rather than replayed. Records now keep a hash keyed with the node's new secrets key, `<data_dir>/secrets.key` (made on first start, mode 0600), or `TELLTALE_SECRETS_KEY` / `[node] secrets_key_file`.
- **Plugins and the self-update** no longer inherit `TELLTALE_SECRETS_KEY`, `TELLTALE_SECRETS_PREVIOUS_KEY`, `TELLTALE_BOOTSTRAP_ADMIN_PASSWORD`, `TELLTALE_BOOTSTRAP_ADMIN_PASSWORD_HASH`, or `TELLTALE_TOKEN`.
- **The Git webhook** answers a refused request with a plain 401 (the log says why), and an empty `webhook_secret_file` refuses every webhook.
