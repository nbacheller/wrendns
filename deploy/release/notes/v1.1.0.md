## Fixed

- **Syslog over TCP or TLS no longer loses events while the collector is down.** The sink keeps the event in hand, retries the connection with a growing pause, and queues new events in its buffer (`max_buffer`). Events that no longer fit, or that are still waiting when the sink stops, are counted in the sink's dropped figure (and `wrendns_sink_dropped_total`). A UDP datagram that cannot be sent is counted too. This fixes the 1.0.0 known issue.

## Upgrading

- **A recursive upstream (`recursive://`) is stricter about what it asks and what it accepts (DNS-902, ADR-1094).** Four things change:
  - `ecs` on a `recursive://` upstream is now refused when the configuration is checked (the field is named, `upstream[N].ecs`), so a start or reload with `ecs = "client"` or a subnet there fails. Remove the line or set it to `strip`: a recursive upstream asks authoritative servers, which never got a client subnet, so the setting did nothing.
  - It no longer asks servers at loopback, unspecified, link-local, multicast or broadcast addresses, and asks private addresses (RFC 1918, 100.64.0.0/10, fc00::/7) only inside its stub zone. A public zone that delegates only to such addresses now ends as SERVFAIL (extended error 22). A stub zone whose servers are loopback or link-local, or an authoritative server on this host or network for a real zone, stops working until you set `allow_local_servers = true` (loopback and link-local) or `allow_private_servers = true` (private, outside a stub zone) under `[upstream.recursive]`, or in the Upstreams page (Advanced view). The configuration check warns about a stub zone with loopback or link-local servers. A forward sent to such a server with "These servers only know this domain" is saved by the web UI without the setting: define that upstream in the configuration file instead.
  - A NSEC3 "no such name" or "no such record" answer with 51 to 100 hash iterations used to validate as secure; it is now answered without AD (RFC 9276).
  - One with 101 to 500 iterations used to be SERVFAIL; it is now answered without AD too. Above 500 it is still refused as bogus.
- **A listener on a public address now answers only a known device key.** `require_client_id` is on by default for a `dot`, `doh`, `doh3` or `doq` listener bound to a public address (any address that is not loopback, RFC 1918, CGNAT 100.64.0.0/10, link-local or unique-local), and for one bound to every address (`0.0.0.0`, `[::]`) when the host holds a public IPv4 address on an interface; it is off by default otherwise, so a Pi behind a router with a private address only, and a host whose only public address is IPv6 (the node warns there), keep an ungated wildcard listener. If the node cannot read its interface list it gates the wildcard listener and says so in the log. The host's addresses are read at start and at every reload: an address that appears later is picked up at the next reload, and the health note `listener_gate_stale` says when the host's addresses changed since the listeners were bound. If your configuration has such a listener and never set the flag, the first start of 1.1.0 refuses every client that carries no key (DNS-901, ADR-1090). The node tells you three ways: a start-up log line naming the listener and the setting, a health note (`listener_gate_default`) with a notice in **Settings → System → Listener access**, and every refusal is counted in `wrendns_client_id_refused_total`. To keep the new behaviour, set `require_client_id = true` on that `[[listen]]` entry; to keep an open listener (only `[access] allowed_networks` then keeps it from being an open resolver), set `require_client_id = false`, which logs a warning at start and at every reload (whether the file or the web UI set it). Either value clears the health note, and a configuration reload applies it without a restart. An admin can also set it per listener in **Settings → System → Listener access** (Default, On or Off, reviewed and audited like the other guarded settings; a file that sets the flag wins and locks the control). `udp` and `tcp` listeners are unchanged: they carry no key.
