## Upgrading

- **A listener on a public address now answers only a known device key.** `require_client_id` is on by default for a `dot`, `doh`, `doh3` or `doq` listener bound to a public address (any address that is not loopback, RFC 1918, CGNAT 100.64.0.0/10, link-local or unique-local), and off by default otherwise. If your configuration has such a listener and never set the flag, the first start of 1.1.0 refuses every client that carries no key (DNS-901, ADR-1090). The node tells you three ways: a start-up log line naming the listener and the setting, a health note (`listener_gate_default`) with a notice in **Settings → System → Listener access**, and every refusal is counted in `wrendns_client_id_refused_total`. To keep the new behaviour, set `require_client_id = true` on that `[[listen]]` entry; to keep an open listener (only `[access] allowed_networks` then keeps it from being an open resolver), set `require_client_id = false`, which logs a start-up warning. Either value clears the health note, and a configuration reload applies it without a restart. An admin can also set it per listener in **Settings → System → Listener access** (Default, On or Off, reviewed and audited like the other guarded settings; a file that sets the flag wins and locks the control). `udp` and `tcp` listeners are unchanged: they carry no key.
